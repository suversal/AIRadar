# 管理后台同步与内容管理优化设计

日期：2026-07-11  
状态：方案 A 已确认

## 目标

修复手动同步写入 embedding 时引用不存在文章 ID 的外键错误；在不新增台账字段的前提下增强运行台账；将同步进度压缩到按钮内；内容管理按配置出的主信源筛选并按抓取时间倒序。

## 数据一致性

缓存查询除评分与元数据外返回数据库真实 `raw_article_id`。流水线按 `url_hash` 命中已有文章时，将本轮标准化对象的 ID 替换为该真实 ID，确保 raw article、embedding、processed article 和 event cluster 使用同一主键。

## 运行台账与同步按钮

台账使用现有 `pipeline_runs` 数据，展示开始、结束、耗时、状态、抓取数、AI 处理数、事件簇数、跳过明细和失败错误。运行中记录实时显示已运行时长；失败错误用可展开区域显示完整内容。

同步按钮运行时显示 `同步中 mm:ss`，成功后显示 `完成 · N 条 · mm:ss`，失败后显示 `失败 · mm:ss`。不再在按钮下方显示逐步状态文字；详细错误由台账承担。

## 内容管理

筛选选项来自当前配置的信源。筛选值为 `source_id`，只匹配事件当前主文章的信源。API 返回的 `main_source` 增加 `id`。管理接口先按 `crawled_at` 倒序、再按 `published_at` 倒序排列，然后进行筛选与分页。标题、分类、主信源和分页参数相互保留。

## 验证

增加 ID 复用回归测试、API 主信源筛选与排序测试、Web 结构测试，并运行完整 Python 测试、TypeScript 类型检查和 Next.js 生产构建。
