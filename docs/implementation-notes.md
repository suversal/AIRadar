# Suversal AI Radar Implementation Notes

## Decisions Locked For The First Milestone

- Prioritize data quality before frontend polish.
- Produce a concise Markdown daily report and JSON payload.
- Support OpenAI, Kimi/Moonshot, and DeepSeek chat providers, but keep a fake deterministic provider for local dry runs.
- Use broad first-batch coverage: official sources, HN, arXiv, GitHub, Reddit, and Chinese media.
- Keep source failures isolated and visible instead of blocking the whole run.
- Crawlers fetch the full feed/API result (`fetch(limit=None)`); the retired `crawl_limit` and old global `DAILY_CANDIDATE_LIMIT` no longer bound intake. Volume is controlled after metadata fetch by each source's `config.recent_days` (default `1`, `0` = no date restriction), editable from the admin source manager.
- Intake flow (2026-07-12 evening, user-specified 4 steps): (1) crawlers fetch **feed metadata only** (rss/hn mark articles `body_fetch=deferred`; `use_feed_content_only` sources exempt) and new articles are **persisted immediately** after the crawl phase (`insert_missing_raw_articles`, status='raw' = 未入选) so data is visible before AI runs; (2) already-stored articles are skipped — including stored non-AI verdicts (rows kept as skip markers; this deliberately reverses the same-day "drop non-AI rows" decision, so each non-AI article is judged exactly once); (3) prefilter runs on feed title+description; (4) only prefilter survivors fetch the full page (`prefer_full_page_content`, per-domain ≥2s throttle since fetches now run inside the AI concurrency pool), then the no-content gate, then scoring. A crawl round dropped from 47min (2445 per-article page fetches up front) to seconds.
- Configurable date window + live persistence: `filter_articles_published_on` uses Asia/Shanghai and applies each source's `recent_days`; `0` bypasses the date window for finite curated feeds such as AI HOT. Every scored article is persisted immediately via `on_article_processed` → `persist_single_article_to_database` (raw+processed+embedding, idempotent, best-effort; clusters/report still land in the final full persist), so the DB grows during the run instead of only at the end. Cached articles reuse stored full content and embeddings unless a source-specific content extraction version invalidates the body, scoring and translations together.
- Preserve structured original article content when feeds provide it, including paragraph blocks and image URLs for event detail pages.
- Enrich selected GitHub Trending repositories with README content after report selection, with short-description fallback on GitHub API errors or rate limits.
- Generate optional Chinese translation blocks only for selected English main articles, so detail pages can offer 原文/译文 comparison without translating every candidate. GitHub README Markdown is treated as canonical original content and is rendered directly instead of being translated into the body view.
- Keep `/latest` as the selected feed. Search stays out of `/latest`; `/all` owns all-dynamics filters and inline search. `/daily`, `/weekly`, and `/monthly` own report reading. Topics and bookmarks are implemented; Agent/About/Changelog/Feedback are intentional static product pages rather than placeholders.
- Structured Telegram RSS sources are trusted only for AI-topic relevance: they skip the prefilter call but still pass through normal scoring thresholds. Their RSS descriptions are parsed into semantic blocks and never become event main sources.
- Event clustering uses two forms of evidence: embedding similarity and exact canonical references found in `source_list` blocks. When clusters consolidate, `event_cluster_redirects` preserves old event URLs.
- Manual article submissions remain private drafts in `article_submissions` until an explicit publish transaction materializes raw/processed/event/report-visible data. URL import, rich-text authoring, AI processing, manual overrides and image upload are protected by independent environment feature flags.

## Current Engineering Shape

- `apps/api/app/models/domain.py`: pure domain dataclasses used by tests and scripts.
- `apps/api/app/crawlers`: RSS/Atom, HN, GitHub, sitemap, Hugging Face Papers, AttentionVC, V2EX and structured Telegram adapters. `base.fetch_url_text` is the shared HTTP helper with a browser-like User-Agent and retry/backoff. `run.crawl_sources` groups sources by domain and crawls domain groups in parallel while keeping same-domain requests serial. Full-page extraction is semantic-block based and source-profiled; arXiv, Google/GitHub blogs, DeepMind, Latent Space, Hugging Face, NVIDIA, Anthropic, QbitAI, IT之家 and WeChat have targeted boundaries or cache versions. Extracted blocks can represent headings, paragraphs, lists, quotes, callouts, tables, code, images, video and X embeds.
- `apps/api/app/services`: AI boundary, scoring, clustering, and report generation. `ai_service.py` includes OpenAI, Kimi/Moonshot, DeepSeek, and fake providers.
- `apps/api/app/services/daily_report_service.py`: daily JSON includes `source_language`, `original_url`, optional `original_markdown`, README diagnostics, `original_paragraphs`, `original_images`, `original_blocks`, and optional `translated_paragraphs`/`translated_blocks` for the main article in each event.
- Persistence writes the full lineage across 17 tables: source/raw/processed content, embeddings, translations, event clusters and redirects, daily/period report snapshots, article/event overrides, pipeline runs, refresh schedule and manual submissions. Clusters are written before processed articles because `processed_articles.event_cluster_id` is a foreign key. The 2026-07-17 local database has one embedding row per processed article.
- Event/cluster ids are content-derived (`e` + sha256 of the main article id, 12 hex chars) so links and bookmarks survive report regenerations.
- Incremental processing: the pipeline accepts `cached_results` keyed by `url_hash` (loaded from Postgres by the CLI and the refresh service). Cached articles reuse AI scoring output and translations; deterministic math (freshness weighting, thresholds, clustering) is recomputed every run. `--no-cache` forces full reprocessing.
- `GET /api/public/events` reads `processed_articles` joined with raw articles and sources in database mode (rejected articles included — "全部 AI 动态" is genuinely all processed dynamics), falling back to daily-report aggregation in JSON mode. `GET /api/public/events/{id}` serves one event with full original/translated content; the web event page uses it when an id is not in the latest selected payload.
- Period reports: `period_summary_service` builds weekly/monthly issues keyed by ISO period (`2026-W28`/`2026-07`) with an AI-written mainline (summarize_period on every provider, top-40 events as input, deterministic fallback on failure). refresh_service regenerates the enclosing week+month after each daily report. Public routes accept issue keys or dates, merge the persisted mainline over live aggregation (`generated` flag), and expose `/reports/{kind}/archive` plus `/reports/daily/archive`. The web period pages render the AI mainline with theme notes and an issue archive sidebar; the daily page has a month-grouped date archive and prev/next paging.
- Scheduling: `scripts/run_scheduled_refresh.sh` (lock-guarded crawl + pipeline, logs to `data/logs/refresh.log`) with a launchd template at `infra/launchd/com.suversal.ai-radar.refresh.plist` (every 2h). Installation requires the user to run the launchctl commands in the README.
- `apps/api/app/pipeline/runner.py`: in-process pipeline orchestration for Phase 0. Candidate AI prefiltering, scoring, and embeddings can run concurrently through `ai_concurrency`; selected GitHub report articles can receive README original content, and selected English report articles can receive bounded paragraph translation before JSON generation unless the selected README is already Chinese. One-off audit runs can set `skip_prefilter=True` to score and report every candidate instead of dropping non-AI-prefiltered items.
- `apps/web/app/latest/page.tsx`: AIHOT-style selected homepage with fixed sidebar, reserved menu labels, category tabs, top hotspots, date-collapsible event stream, and no inline search box in this iteration.
- `apps/web/app/all/page.tsx`: AIHOT-style all AI dynamics page with source/category filters, inline search, date-collapsible timeline, score badges, optional original image, tags, recommendation reason and article detail links. In database mode it lists processed articles independently instead of collapsing every event to one main row.
- `apps/web/app/reports`: shared AIHOT report shell, report mode tabs, daily digest helpers, and period report helpers.
- `apps/web/app/daily/page.tsx`: AIHOT-style daily report page with highlights, stats, category sections, Markdown copy and archive paging through query parameters.
- `apps/web/app/weekly/page.tsx` and `apps/web/app/monthly/page.tsx`: AIHOT-style period report pages with mainline summary, stats, highlights, and theme sections. They consume `GET /api/public/reports/weekly[/{date}]` (trailing 7 days) and `GET /api/public/reports/monthly[/{YYYY-MM}]` (calendar month), which aggregate daily reports over the true period range. Like latest/daily, all new endpoints read the repository when `DATABASE_URL` is set and fall back to `data/reports/*.json` otherwise.
- `apps/web/app/event/[id]/page.tsx`: event detail keeps the AIHOT left navigation visible while reading, with recommendation reason, AI summary, original content, README Markdown rendering when available, optional AI translation/original toggle, tags, and read-original actions.
- `scripts`: local CLI entrypoints for seed, crawl, pipeline, and report output. `run_pipeline_once.py` supports `--ai-concurrency` and `--skip-prefilter`; API refresh reads `AI_PIPELINE_CONCURRENCY`.
- `infra`: Docker Compose and PostgreSQL schema with pgvector.

- Hotspots: `GET /api/public/hotspots?hours=48&limit=5&category=&q=` powers the `/latest` 当前热点 board. Duplicate articles remain visible in feeds, while clusters serve hotspot ranking and the event-detail coverage panel. Automatic consolidation now keeps persistent event redirects; manual merge/split UI and pgvector database top-k are still out of scope.
- Taxonomy: `app/services/taxonomy.py` is the single category standard — 8 scoring categories (with per-category thresholds) map to 5 display categories + 全部 (模型/产品/行业/论文/技巧). All payloads emit display-key `category`, Chinese `category_label`, and `scoring_category`; the events API category filter compares in display space; `scoring_system_prompt()` (shared by all chat providers) constrains the model to the 8-value enum. `apps/web/lib/taxonomy.ts` mirrors the standard for filter options.
- Topics: `app/services/topics.py` registers three groups (公司与模型 12 topics by company keywords, 技术方向 8 topics by technique keywords, 内容形态 = display categories). ASCII keywords match on word boundaries, CJK by substring. `GET /api/public/topics` returns grouped 30-day counts; `GET /api/public/events?topic=` filters. `/topics` page links each card to `/all?topic=`.
- Visual identity "琥珀信号": design tokens in `apps/web/app/globals.css` via Tailwind `@theme` (canvas/panel/line/signal/cool/ink scales), CJK system font stack, `.readout` mono utility for scores/clocks. Brand is AI·RADAR. Shared `components/sidebar.tsx` + `components/nav.ts` replace per-page sidebars; `components/radar-status.tsx` is the signature instrument bar; `components/static-page.tsx` shells the four static pages (/agent /about /changelog /feedback). Single dark theme by design.

- Admin console: `require_admin` guards every `/api/admin/*` route. Dashboard covers table counts, source health, run ledger, manual refresh and schedule. Source management supports create/edit/enable/test/delete with article-protection on delete. Content management supports filtering, sorting, editorial overrides, hide/restore, cascading delete and credentialed preview of hidden articles. Feature-gated draft management supports manual URL/rich-text submissions through processing and publication.

## Next Milestone

- Run a 14-day source-quality ledger and prune or constrain sources using editorial contribution, not transport success alone.
- Finish real-world acceptance of the manual article workflow and add operation auditing before enabling it broadly.
- Turn source-profile extraction fixtures into an ongoing regression suite and surface stale/extraction/translation failures in admin monitoring.
- Move similarity lookup to pgvector top-k and keep redirect consistency checks around cluster consolidation.
- Clear the 22 Ruff issues, add CI for pytest/Ruff/typecheck/build, then establish mobile, accessibility and performance baselines.
- Defer Celery/Redis, public RSS/API productization, MCP, multi-admin permissions and manual event merge/split until the quality baseline is stable.
